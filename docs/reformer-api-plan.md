# План правок API `@reformer`

Рабочий план на изменения в самой библиотеке. Соседний документ
[reformer-code-organization.md](./reformer-code-organization.md) описывает **что** мы выяснили и как
организовывать код; здесь — **как это внедрять**: пакет, размер, совместимость, миграция, проверка.

Оговорка о достоверности: выводы сделаны по опубликованному API и скомпилированному `dist`
установленных версий (`core@10.1.0`, `cdk@11.2.0`, `renderer-react@10.2.0`, `renderer-json@11.0.0`).
Исходников библиотеки я не видел, поэтому сигнатуры — предложения, а не готовые патчи; места правок
названы по наблюдаемому поведению.

---

## Порядок внедрения

Три волны. Первая — почти без риска и даёт больше всего; вторая меняет контракты и требует
депрекейшена; третья — новые сущности.

| Волна | Пункты | Смысл |
|---|---|---|
| **1. Тихие баги → громкие** | B1, B2, B3 | чинит то, на чём спотыкается каждый мост и каждая форма |
| **2. Контракты** | B4, B5, B6 | убирает обязательный адаптер и двойную передачу схемы, типизирует пути |
| **3. Новые сущности** | B7, B8 | контракт шага визарда и вывод `initialValue` из модели |

## Волна 1

### B1. Рантайм-пропы ноды должны доезжать до контрола

**Пакет:** `renderer-react` · **Размер:** S · **Ломающее:** практически нет

**Проблема.** `updateComponentProps({ options })` пишет в ноду формы, а листовой рендерер спредит в
контрол `componentProps` **из схемы**. Если у контрола есть `FieldAdapter`, нода до него не доходит —
рантайм-обновление теряется целиком.

**Как проявилось.** Поведение грузило модели авто по выбранной марке
(`loadOptionsOn(model.$.carBrand, form.carModel, fetchCarModels)`), запрос отрабатывал, опции
приходили — а селект оставался пустым («No data»). Диагноз занял час; обошли тем, что сделали этот
контрол единственным **без** адаптера, чтобы он получил ноду и прочитал пропы сам.

**Предложение.** Мержить реактивные пропы ноды поверх схемных до применения адаптера:

```ts
// листовой рендерер, до buildAdaptedFieldProps
const runtime = useFormControl(fieldNode).componentProps;      // реактивно
const componentProps = { ...node.componentProps, ...runtime }; // рантайм переопределяет схему
```

**Совместимость.** Порядок приоритета стоит зафиксировать в доках: схема — дефолт,
`updateComponentProps` — переопределение. Риск только у тех, кто полагался на обратное.

**Проверка.** Тест: поле с `options` из схемы + `updateComponentProps({ options })` в поведении →
контрол получает вторые. Отдельно — тот же тест для контрола с адаптером и без.

### B2. `validateModel(…, { touch })`

**Пакет:** `core/validation` · **Размер:** S · **Ломающее:** нет (опция)

**Проблема.** `shouldShowError = invalid && (touched || dirty)`. Любой инициированный пользователем
прогон обязан сначала позвать `form.markAsTouched()`, иначе валидация отрабатывает невидимо.

**Как проявилось.** Дважды за одну работу, и оба раза — только в браузере: визард блокировал переход,
ошибки были проставлены в ноды, на экране — ничего. Снаружи это «кнопка не работает».

**Предложение.**

```ts
validateModel(model, schema, { touch: true })
```

Важная деталь: помечать **только поля, которые схема проверяла**. Сейчас приложение вынуждено звать
`markAsTouched()` на корне формы, из-за чего следующий шаг встречает пользователя «тронутыми» полями
ещё до ввода. Раннер знает список задействованных сигналов — он может пометить точечно.

**Миграция.** Опция аддитивна. В доках по визардам заменить рецепт «не забудьте markAsTouched» на
`{ touch: true }`.

**Проверка.** Прогон на нетронутой форме: без опции — `shouldShowError === false`, с опцией — `true`
у полей схемы и `false` у остальных.

### B3. Диагностика вместо тишины

**Пакет:** `renderer-react` + `renderer-json` · **Размер:** S · **Ломающее:** нет (только dev)

**Проблема.** Сигналы разного качества: неизвестный `$component` бросает, неизвестный `$dataSource`
молчит, промах `$model` пишет `warn`, промах селектора не делает ничего.

| Ситуация | Сейчас | Предлагается (dev) |
|---|---|---|
| `schema.node('wizrd')` | тишина | warn: узла нет + список известных селекторов |
| `$dataSource(NAME)` не зарегистрирован | строка уезжает в проп значением | warn; ошибка в `validateSchema` |
| `$model(path)` без сигнала | `console.warn` | запись в панель ошибок схемы |
| `renderBehavior` сменил идентичность между рендерами | тишина | warn: дерево пересобирается каждый рендер |
| сырой контрол без адаптера | React-варнинги про неизвестные атрибуты | warn с именем компонента и подсказкой |
| `initialValue` не совпал с формой элемента | элемент без сигналов, поля не рендерятся | warn со списком недостающих ключей |

**Отдельным пунктом:** `validateSchema` сегодня — dev-only проп, а `convertJsonToM1Tree` при битой
схеме бросает **до** рендера. В проде это белый экран вместо панели ошибок. Предлагаю разрешить
включать проверку в проде осознанно (ценой веса ajv) либо ловить бросок конвертера и показывать ту же
панель.

**Проверка.** Юнит-тесты на каждый пункт таблицы: вызвать неправильно — увидеть ровно одно
предупреждение с понятным текстом.

## Волна 2

### B4. `control` в контрол — только по запросу

**Пакет:** `renderer-react` · **Размер:** M · **Ломающее:** да, смягчаемо

**Проблема.** Без адаптера рендерер подмешивает в контрол проп `control` (ноду формы), и сырой
компонент чужой дизайн-системы разливает его в DOM. Из-за этого адаптер заводят почти каждому
контролу — не ради перевода диалекта, а ради `strip`.

**Как проявилось.** В нашем мосте из шести контролов четыре имели адаптер вида `{ strip: ['label'] }`
плюс мелкая нормализация пустого значения. То есть три четверти адаптеров существовали ради обхода
дефолта.

**Предложение.** Не передавать ноду по умолчанию; передавать по явному запросу — либо флагом
адаптера, либо статикой компонента (второе не требует адаптера вовсе):

```ts
interface FieldAdapter { passControl?: boolean }
MyField.reformerNeedsControl = true;   // для полей ui-kit, которые читают ноду сами
```

**Совместимость.** Ломает тех, кто читает `control` из пропов, не имея адаптера, — это ровно поля
`@reformer/ui-kit`. Поэтому: сначала проставить статику в ui-kit, выпустить минор с предупреждением
«контрол читает control, но не объявил `reformerNeedsControl`», в следующем мажоре сменить дефолт.

**Взаимодействие с B1.** Вместе они убирают большинство адаптеров: после B1 контролу не нужна нода
ради рантайм-пропов, после B4 — не нужен адаптер ради их сокрытия.

**Проверка.** Регистрация сырого antd-контрола без адаптера: в DOM не должно появиться ни `control`,
ни React-варнингов.

### B5. Схема передаётся один раз

**Пакет:** `renderer-json` · **Размер:** M · **Ломающее:** нет (аддитивно)

**Проблема.** Сейчас схема идёт дважды: в `convertJsonToM1Tree(schema, registry, model)` для сборки
формы и пропом `schema` в `JsonFormRenderer` для рендера. Ничто не мешает передать в эти два места
разные объекты; сборку при этом обязательно выполнить ровно один раз — требование, живущее в
комментариях прикладного кода.

**Предложение.**

```ts
export function createJsonForm<T>(cfg: {
  schema: JsonFormSchema<T>;
  registry: ComponentRegistry;
  initial: T;
  behavior?: FormBehaviorFn<T>;
}): { model: FormModel<T>; form: FormProxy<T>; schema: JsonFormSchema<T> };

<JsonFormRenderer form={jsonForm} renderBehavior={behavior} validateSchema={import.meta.env.DEV} />
```

Плюс React-обёртка в `cdk`, которая берёт на себя «создать ровно один раз»:

```ts
const jsonForm = useJsonForm({ schema, registry, initial, behavior });
```

**Важная деталь.** Пересоздание модели между рендерами теряет введённые данные, поэтому внутри нужен
**ленивый инициализатор `useState`**, а не `useMemo`: `useMemo` по контракту React — кэш-подсказка,
и React вправе его сбросить. Мы наступили на это в проекте и переписали хук именно так.

**Совместимость.** Старый путь остаётся; новый — рекомендуемый в доках.

**Проверка.** Тест: два рендера подряд с вводом между ними — значение сохраняется; попытка передать в
рендерер схему, отличную от собранной, — ошибка на этапе типов.

### B6. Типизированные операторы и схема

**Пакет:** `renderer-json` · **Размер:** M · **Ломающее:** нет (аддитивно)

**Проблема.** `$model(personalDate.firstName)` — опечатка ловится только `console.warn` в рантайме,
поле молча не рендерится. Плюс каждая страница пишет `as unknown as JsonFormSchema`, потому что
импортированный JSON типизируется как словарь строк.

**Предложение.**

```ts
type ModelOp<T> = `$model(${Path<T>})`;                    // Path<T> — рекурсивные пути модели
export function defineJsonSchema<T>(s: JsonFormSchema<T>): JsonFormSchema<T>;
```

Для схемы, приходящей строкой с сервера, остаётся нетипизированный путь — и хорошо, что два сценария
выглядят в коде по-разному: один проверяется компилятором, второй обязан проверяться `validateSchema`.

**Ограничение, которое стоит признать в доках.** Шаблонные литеральные типы не покрывают индексы
массивов и `$template`-поддеревья, где пути относительны элементу. Для них останется рантайм-проверка.

**Проверка.** Тип-тесты: `$model(loanAmoun)` не компилируется, `$model(personalData.firstName)` —
компилируется, относительный путь внутри `$template` — тоже.

## Волна 3

### B7. Контракт шага визарда

**Пакет:** `cdk` (+ адаптация в `renderer-json`) · **Размер:** L · **Ломающее:** нет

**Проблема.** Мост под каждый UI-kit заново решает три вопроса: нумерация шагов, момент вызова
пошаговой валидации и способ отдать значения в submit.

**Как проявилось.** Наш мост под hexa-ui разошёлся с cdk-шным `FormWizard` по всем трём: hexa считает
шаги с нуля, cdk — с единицы; hexa зовёт `onFinish()` без аргументов, а поведение из примера ждало
`onSubmit(values)`; императивной навигации у hexa нет вовсе, пришлось делать визард контролируемым и
отдавать свой ref-handle.

**Предложение.** Описать шаг как узел со своим селектором и правилами, а нумерацию оставить деталью
реализации моста:

```ts
interface WizardStepContract<T> {
  selector: string;
  validate?: (ctx: { model: FormModel<T>; form: FormProxy<T> }) => boolean | Promise<boolean>;
}

interface WizardHostContract<T> {
  steps: readonly WizardStepContract<T>[];
  goToStep(selector: string): boolean;
  submit(): Promise<T | null>;
}
```

Тогда мост реализует ровно одно: «покажи шаг, спроси разрешение на переход». Мы это уже написали
на стороне приложения (`defineSteps` + селекторы шагов) — код можно взять как эскиз.

**Проверка.** Контрактные тесты, которые прогоняются против двух мостов (ui-kit и любой внешний):
переход блокируется на невалидном шаге, `goToStep` на несуществующий селектор возвращает `false`,
submit отдаёт снимок значений.

### B8. `initialValue` массива выводится из модели

**Пакет:** `renderer-json` · **Размер:** S · **Ломающее:** нет

**Проблема.** Форма элемента массива дублируется: в `form.json` (`initialValue`) и в blank-фабриках
модели. Частичный объект даёт элемент без сигналов — поля просто не рендерятся, ошибки нет.

**Предложение.** При отсутствии `initialValue` строить пустой элемент по форме модели; при наличии —
в dev сверять ключи и предупреждать о расхождении (это часть таблицы из B3).

---

## Что не стоит менять

Слоистость (`layout` в JSON — правила в TS — поведение модели — render-behavior отдельно) себя
оправдала буквально: схема на 157 узлов переехала на другую дизайн-систему без единой правки
структуры. Адаптеры как понятие тоже нужны — киты действительно расходятся диалектами
(`checked` + DOM-событие, `fileList`, `(value, option)`). Многословие идёт не от этой архитектуры,
а от отсутствия сахара над ней и от дефолтов, описанных в B4 и B5.
